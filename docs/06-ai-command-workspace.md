# Grounded AI command workspace

The command workspace is the conversational surface over work the autonomous sentinel has
already performed. It is not a second incident detector and it is not a generic chatbot.

## Why this remains AI-native

- The answer is generated by the same model choke point as detection, investigation, and
  remediation (`src/llm/client.js`). There is no templated answer fallback.
- Each request is grounded in the current health reading, open incidents, emerging risks,
  reviewable proposals, and the latest 90 evidence records.
- Operational claims may cite only evidence ids that exist in the ledger. Unknown `[E#]`
  references are rejected before a response reaches the UI.
- Suggested actions are navigation into an existing incident or reviewable proposal. The
  workspace cannot approve or execute a proposal; the existing human gate remains intact.
- Conversation turns, role, context, citations, limitations, and suggested action are
  persisted under `copilotConversations` in `store/state.json` for auditability.

## API contract

`POST /api/copilot`

```json
{
  "message": "What needs my attention right now?",
  "conversationId": "C-... or null",
  "role": "operations | executive | engineer",
  "context": {
    "view": "dashboard | incidents | capabilities",
    "incidentId": "INC-1 or null"
  }
}
```

The structured response contains a headline, cited answer, confidence, explicit limitations,
two or three contextual follow-up prompts, and at most one validated navigation action.

`GET /api/copilot/:conversationId` returns the persisted thread so context survives page
navigation and browser reloads.

## Failure behavior

If model capacity is unavailable, the UI says so explicitly. It does not fabricate a plausible
answer from deterministic templates. Monitoring and previously recorded evidence remain
available while grounded conversational answers are paused.
